- feat#N01 Android + iOS: requested by Jeremy after #124 commenter `01disney` reinforced that the candidate-strip left `X` is too small/hard to press during thumb typing and asked whether it can be made the same size as the smiley icon. Jeremy's locked decision (2026-06-29): make the dismiss / clear-code button **1.5× its current width** on both platforms, keeping height, color, corner style, glyph, and tap semantics intact, and not changing the keyboard delete/backspace key. Android = `candidate_dismiss_button_width` 21sp → 31.5sp (one dimen, cascades everywhere); iOS = new `Chevron.dismissButtonWidth(isPad:)` = `buttonWidth/2 * 1.5` (30pt phone / 39pt iPad) across the 3 call sites. Plan + TDD tests in `docs/FEAT_#N01.md`. Current state: planned, pending implementation/verification on both platforms.
- feat#N02 Android + iOS: requested by Jeremy on 2026-06-30. Add a new computer-numpad-style keyboard layout option for Array10 (`行列10`). This layout should use the computer numeric keypad row order, which is opposite to the phone-style numeric keypad order: top row `7 8 9`, then `4 5 6`, then `1 2 3`, with `0` on the bottom row as appropriate for each platform layout. Keep the existing phone-style Array10 numeric layout available for users who prefer phone keypad ordering. Current state: confirmed product direction, pending design/implementation and platform-specific verification.
- feat#140 Android + iOS: from GitHub issue #140 (`homchang`) — 四碼倉頡 (cj4, a four-code Cangjie) uses the `;` key as a root, which LIME's Cangjie keyboard lacks. Add a per-IM toggle on the **cj4** IM details page (always shown, default off). When on, programmatically (no new static layouts): on iPhone + Android add a `;` key at the right end of the `lime_cj` / `lime_cj_number` asdf home row (fill the front/ending spacer → flush 10-key row); on iPad rewrite the existing `；|：` key to `:|;`; and force `hasSymbolMapping = true` for cj4 (via a new `SearchServer.setSymbolMapping` called from the keyboard side) so `;` composes as a root. Scope: `lime_cj` + `lime_cj_number` only. The `;`-mapping Cangjie table is user-supplied. Full design + spec/doc/manual touch points in `docs/#140_ISSUE.md`. Current state: implemented on both platforms on branch feat/140-cangjie-semicolon (iOS layout transform + controller wiring + unit test; Android programmatic key injection + KeyboardId cache variant + setSymbolMapping wiring); both platforms compile and the iOS transform unit test passes. **Blocked (decision 2026-06-30):** #140 will not ship before `docs/INIMKEYS_UNIFICATION.md` (the `inImKeys` acceptance unification) — the branch's `setSymbolMapping` / forced `hasSymbolMapping` / `refreshImKeys`-append are placeholders to be reworked so cj4's `;` flows through `inImKeys`; the two land together. Pending: the unification, then on-device/emulator visual verification, then commit.

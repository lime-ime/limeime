- feat#N03 Android + iOS: requested by #124 commenter `01disney` in https://github.com/lime-ime/limeime/issues/124#issuecomment-4851877127 and approved by Jeremy on 2026-07-01. Extend the existing long-press `123` shortcut to switch directly to the phone/simple numeric keyboard (`phone_simple`) for all IM keyboards/layouts that have an independent `123` key, not only the English layout. Exclude phone-family layouts (`phone*`, including `phone_simple` and phone English/shift variants) so phone-layout `123` behavior is not recursively changed. Normal tap on `123` should keep the existing symbol-keyboard behavior; only long-press gains the direct phone-simple shortcut. Apply parity on Android and iOS where equivalent layouts/keys exist; implementation should audit each platform's layout XML/Swift keyboard definitions rather than assuming all keyboards expose `123` the same way.
- feat#N02 Android + iOS: requested by Jeremy on 2026-06-30. Add a new computer-numpad-style keyboard layout option for Array10 (`行列10`). This layout should use the computer numeric keypad row order, which is opposite to the phone-style numeric keypad order: top row `7 8 9`, then `4 5 6`, then `1 2 3`, with `0` on the bottom row as appropriate for each platform layout. Keep the existing phone-style Array10 numeric layout available for users who prefer phone keypad ordering. Design: it's a new entry (`computernum` → `computer_simple`) in the global `keyboard` table, seeded insert-if-absent on open (no schema change, no DB version bump); the existing global keyboard picker selects it, so `phonenum`/`phone_simple` stays untouched. Full design + the Android hardcoded-resolution gotcha in `docs/FEAT_#N02.md`. Current state: implemented on both platforms; unit tests green on both (iOS RED→GREEN; Android 2/2); Android compiles. **Crash fixed (2026-07-01):** on Android, selecting computer numpad for Array10 crashed on switch because `LIMEKeyboardSwitcher.getKeyboardXMLID` is a hardcoded `imkb`→`R.xml` switch that returned `0` for the unmapped `computer_simple` (added the case); also fixed Array10 auto-commit, which gated on `currentSoftKeyboard.contains("phone")` and missed `computernum`. iOS was unaffected (loads layouts by filename). The crash-fix commit `5c8fdf7c814b` predates the v6.1.27 APK build commit `2a24f54b0d88`, so the Android GitHub APK v6.1.27 contains this implementation; iOS source is on `master`, but iOS user delivery still waits for TestFlight/App Store. Keep normal release QA for visual verification and reporter feedback.

## Pending fixes
- fix#209 iOS: Related-Phrase Management can fail its keyboard-to-Settings editor refresh with `SQLite error 5: database is locked`, after which the screen becomes read-only and the user cannot edit or delete related phrases. Root cause is an unserialized cold-database lifecycle: Settings held its cold connection open (and loaded cold beside the handshake), the keyboard's `DETACH` inside the GRDB transaction failed silently, and the `.done` receipt did not prove release. The issue branch replaces the earlier retry-only slice with a hand-off — Settings closes cold before the request and rebinds before returning on every path, the harvest attaches/commits/detaches/closes before the receipt, and both editors load cold only after the handshake resolves. Real-SQLite measurements of both harvest lock points plus the source-lifecycle contracts pass on Linux (`scripts/test_issue_209_ios_editor_refresh_lifecycle.py`, 18 tests). The new GRDB/XCTest lifecycle cases are written but UNEXECUTED — no Swift toolchain on that host, so Xcode/Xcode Cloud test and archive validation and affected-device runtime confirmation both remain pending. Android does not use this iOS cold/hot editor architecture and remains unchanged. See `docs/#209_ISSUE.md`.

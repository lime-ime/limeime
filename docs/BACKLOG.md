- feat#124 Android: from #124 commenter `01disney` in https://github.com/lime-ime/limeime/issues/124#issuecomment-4786153001 / https://github.com/lime-ime/limeime/issues/124#issuecomment-4788945640. - feat#124 iOS: same #124 request and scope for iOS parity. On the English keyboard layout only, the `123` key should visibly show an ellipsis (`...`) affordance. Normal press should continue switching to the first symbol keyboard, while long-pressing `123` should switch to the phonetic/simple numeric keyboard. Current state: implemented in iOS source on `master`, but iOS delivery still waits for a TestFlight/App Store build. No Android APK can validate the iOS path.
- feat#N01 Android + iOS: requested by Jeremy after #124 commenter `01disney` reinforced that the candidate-strip left `X` is too small/hard to press during thumb typing and asked whether it can be made the same size as the smiley icon. Jeremy's locked decision (2026-06-29): make the dismiss / clear-code button **1.5× its current width** on both platforms, keeping height, color, corner style, glyph, and tap semantics intact, and not changing the keyboard delete/backspace key. Android = `candidate_dismiss_button_width` 21sp → 31.5sp (one dimen, cascades everywhere); iOS = new `Chevron.dismissButtonWidth(isPad:)` = `buttonWidth/2 * 1.5` (30pt phone / 39pt iPad) across the 3 call sites. Plan + TDD tests in `docs/FEAT_#N01.md`. Current state: Android implementation is included in GitHub APK v6.1.27 and iOS source is on `master`; `limeimetw` posted the scoped #124 v6.1.27 update/retest note at https://github.com/lime-ime/limeime/issues/124#issuecomment-4846962493. Keep #124 open pending reporter confirmation and iOS delivery.
- feat#N02 Android + iOS: requested by Jeremy on 2026-06-30. Add a new computer-numpad-style keyboard layout option for Array10 (`行列10`). This layout should use the computer numeric keypad row order, which is opposite to the phone-style numeric keypad order: top row `7 8 9`, then `4 5 6`, then `1 2 3`, with `0` on the bottom row as appropriate for each platform layout. Keep the existing phone-style Array10 numeric layout available for users who prefer phone keypad ordering. Design: it's a new entry (`computernum` → `computer_simple`) in the global `keyboard` table, seeded insert-if-absent on open (no schema change, no DB version bump); the existing global keyboard picker selects it, so `phonenum`/`phone_simple` stays untouched. Full design + the Android hardcoded-resolution gotcha in `docs/FEAT_#N02.md`. Current state: implemented on both platforms; unit tests green on both (iOS RED→GREEN; Android 2/2); Android compiles. **Crash fixed (2026-07-01):** on Android, selecting computer numpad for Array10 crashed on switch because `LIMEKeyboardSwitcher.getKeyboardXMLID` is a hardcoded `imkb`→`R.xml` switch that returned `0` for the unmapped `computer_simple` (added the case); also fixed Array10 auto-commit, which gated on `currentSoftKeyboard.contains("phone")` and missed `computernum`. iOS was unaffected (loads layouts by filename). The crash-fix commit `5c8fdf7c814b` predates the v6.1.27 APK build commit `2a24f54b0d88`, so the Android GitHub APK v6.1.27 contains this implementation; iOS source is on `master`, but iOS user delivery still waits for TestFlight/App Store. Keep normal release QA for visual verification and reporter feedback.
